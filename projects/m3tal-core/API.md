## 🏗️ M3TAL System Architecture

Before diving into commands, let's establish a clear understanding of the M3TAL system's foundational components and their interactions.

### Core Components

*   **CLI Binary (`/usr/bin/m3tal`)**: The user-facing command-line tool, a Go binary installed via APT.
*   **API Daemon (`m3tal-api.service`)**: A Go binary running as a systemd service, listening on `http://localhost:8080`. It manages Docker, maintains the SQLite state database (`/var/lib/m3tal/state.db`), and exposes the core API routes for the Dashboard and CLI.
*   **Dashboard Container (`m3tal-dashboard`)**: A Python/Flask application running in a Docker container. It communicates with the API daemon at `http://host.docker.internal:8080`.
*   **Traefik Gateway (`routing-compose.yml`)**: A Docker container acting as a reverse proxy. It exposes services (like the Dashboard and API) by domain name on host port 80, using a file provider for dynamic routing from `/docker/dynamic/`.
*   **Cloudflared Container (Optional)**: A Docker container for establishing Cloudflare Tunnels, providing zero-config internet access to your services without direct port forwarding.

### 🗃️ Filesystem Contract

The following paths are critical to the M3TAL ecosystem's operation and configuration:

| Path                        | Purpose                                                                                                                                                                                                                                  |
| :-------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/etc/m3tal/.env`           | **Primary Configuration File**. Contains environment variables for M3TAL's core components and user stacks. Managed primarily by `m3tal config wizard` and `m3tal config set`.                                                              |
| `/var/lib/m3tal/state.db`   | **SQLite State Database**. Auto-created and managed by the `m3tal-api.service`. Stores M3TAL's internal state, such as registered stacks and service configurations.                                                                        |
| `/opt/m3tal/stack/`         | **Canonical Stack Directory**. The internal, authoritative location where M3TAL stores its core Docker Compose files (e.g., `routing-compose.yml`) and Traefik dynamic configuration.                                                       |
| `/docker`                   | **User-Facing Stack Directory**. A symbolic link pointing to `/opt/m3tal/stack/`. This is the recommended path for users to place their custom `*-compose.yml` files and Traefik dynamic configuration for new stacks.                     |
| `/docker/users.json`        | **Dashboard Credential Store**. A JSON file containing encrypted user credentials for the M3TAL Dashboard. Managed exclusively by the `m3tal dashpass` command. **Do not edit this file manually.**                                      |
| `/docker/dynamic/`          | **Traefik Dynamic Configuration Directory**. Stores `.yml` files for Traefik's file provider, defining routing rules for services (e.g., `dynamic/api.yml` for the API daemon). Traefik hot-reloads changes in this directory.           |
| `/docker/m3tal-compose.yml` | **Base Dashboard Compose File**. The fundamental Docker Compose definition for the `m3tal-dashboard` container. This file is managed by `m3tal dash up`.                                                                                 |
| `/docker/m3tal-compose.local.yml` | **Local Mode Dashboard Override**. An override file applied when `DASHBOARD_EXPOSE_MODE=local`. It adds a direct port binding to the dashboard. Managed by `m3tal dash up`.                                                                 |
| `/docker/m3tal-compose.traefik.yml` | **Traefik Mode Dashboard Override**. An override file applied when `DASHBOARD_EXPOSE_MODE=traefik`. It adds Traefik labels for routing `dash.${DOMAIN}` to the dashboard. Managed by `m3tal dash up`.                                          |
| `/docker/routing-compose.yml` | **Core Traefik and Cloudflared Compose**. Defines the Traefik reverse proxy and optional Cloudflared tunnel. Part of M3TAL's core stack.                                                                                                |

### 🖥️ Dashboard Access Modes

The M3TAL Dashboard can be accessed in two primary modes, controlled by the `DASHBOARD_EXPOSE_MODE` variable in `/etc/m3tal/.env`.

#### Mode 1: `local` (Default)

*   **Configuration**: Set `DASHBOARD_EXPOSE_MODE=local` in `/etc/m3tal/.env`.
*   **Mechanism**: The `m3tal dash up` command uses the `m3tal-compose.local.yml` override file, which adds a direct port binding, exposing the dashboard container's internal port 8082 to the host at `${DASHBOARD_PORT:-8082}`.
*   **Access URL**: `http://HOST_IP:8082` or `http://localhost:8082`
*   **Requirements**: No Traefik or domain configuration is required.
*   **Best For**: LAN-only setups, initial configuration, first-time users, and local development/testing. It works out-of-the-box on a home server.

    ```bash
    # Ensure local mode is set (this is the default)
    m3tal config set DASHBOARD_EXPOSE_MODE local

    # Start the dashboard in local mode
    m3tal dash up

    # Access via browser
    echo "Access dashboard at http://localhost:8082"
    ```

#### Mode 2: `traefik`

*   **Configuration**: Set `DASHBOARD_EXPOSE_MODE=traefik` in `/etc/m3tal/.env`. Also, ensure `DOMAIN` is set (e.g., `m3tal config set DOMAIN example.com`).
*   **Mechanism**: The `m3tal dash up` command uses the `m3tal-compose.traefik.yml` override, which applies Traefik labels to the dashboard container. When Traefik (running via `routing-compose.yml`) detects these labels, it automatically routes requests for `dash.${DOMAIN}` to the dashboard container's internal port 8082.
*   **Access URL**: `http://dash.YOUR_DOMAIN` (e.g., `http://dash.example.com`)
*   **Requirements**: Traefik must be running (via `m3tal up`), and your `DOMAIN` environment variable must be correctly configured and point to your M3TAL host.
*   **Best For**: Domain-based setups, integrating the dashboard with other services behind Traefik, and leveraging Traefik's advanced routing features.

    ```bash
    # Switch to Traefik mode and set your domain
    m3tal config set DASHBOARD_EXPOSE_MODE traefik
    m3tal config set DOMAIN myhomelab.net

    # Ensure Traefik and other core stacks are running
    m3tal up

    # Start the dashboard with Traefik labels
    m3tal dash up

    # Access via browser
    echo "Access dashboard at http://dash.myhomelab.net"
    ```

### 🐳 Docker / Compose Runtime

M3TAL leverages **Docker Engine** and **Docker Compose V2** as its core container orchestration tools. These are hard dependencies for the system.

*   The `m3tal up` command orchestrates all Docker Compose files ending in `*-compose.yml` found in the `/docker/` directory. This means it runs `docker compose -f /docker/routing-compose.yml -f /docker/my-app-compose.yml up -d`, effectively starting all defined services.
*   The `m3tal dash up` command specifically manages the `m3tal-dashboard` container. It performs the following steps:
    1.  Downloads the latest `m3tal-compose.yml`, `m3tal-compose.local.yml`, and `m3tal-compose.traefik.yml` from GitHub, ensuring your dashboard components are up-to-date.
    2.  Reads the `DASHBOARD_EXPOSE_MODE` from `/etc/m3tal/.env`.
    3.  Starts or updates the dashboard container using the appropriate base (`m3tal-compose.yml`) and override (`m3tal-compose.local.yml` or `m3tal-compose.traefik.yml`) compose files.
*   **User Stacks**: To integrate your own Docker Compose applications, simply place your `*-compose.yml` file (e.g., `my-cool-app-compose.yml`) into the `/docker/` directory. M3TAL will automatically pick it up with `m3tal up`.

### 🚀 Deployment Lifecycle — Day 2 Operations

Adding a new custom stack to your M3TAL system is straightforward:

1.  **Place your Compose file**: Create or copy your Docker Compose file (e.g., `my-media-server-compose.yml`) into the `/docker/` directory.
    ```bash
    # Example: Creating a simple Nginx stack
    sudo nano /docker/nginx-compose.yml
    ```
    ```yaml
    # /docker/nginx-compose.yml
    version: '3.8'
    services:
      nginx:
        image: nginx:latest
        container_name: m3tal-nginx
        restart: unless-stopped
        ports:
          - "8081:80" # Exposed directly for testing, or use Traefik labels
        environment:
          - TZ=America/New_York
        labels:
          # Example Traefik labels for routing:
          # - "traefik.enable=true"
          # - "traefik.http.routers.nginx.rule=Host(`nginx.yourdomain.com`)"
          # - "traefik.http.routers.nginx.entrypoints=web"
          # - "traefik.http.services.nginx.loadbalancer.server.port=80"
    ```
2.  **Configure Environment Variables**: If your stack requires specific environment variables (e.g., API keys, custom ports), define them in `/etc/m3tal/.env`. Use the `m3tal config wizard` for interactive setup or `m3tal config set` for direct updates.
    ```bash
    m3tal config set MY_NGINX_PORT 8081 # If you want to externalize a port
    m3tal config wizard # For interactive configuration of many variables
    ```
3.  **Start All Stacks**: Run `m3tal up` to pull images and start all services defined in the `*-compose.yml` files within `/docker/`, including your new stack.
    ```bash
    m3tal up
    ```

### 🛣️ Traefik Routing Architecture

Traefik acts as the intelligent reverse proxy for your M3TAL ecosystem. It's deployed as a container via `routing-compose.yml` (managed by `m3tal up`).

*   **Entry Point**: Traefik binds to host port 80, serving as the primary HTTP entry point for all domain-based services.
*   **Service Discovery**: Traefik automatically discovers and configures routes for services that have appropriate Docker labels (e.g., `traefik.enable=true`, `traefik.http.routers.myservice.rule=Host(...)`).
*   **Dynamic Configuration**: Traefik uses a file provider to load dynamic routing configurations from `/docker/dynamic/`. Any `.yml` files placed in this directory are hot-reloaded by Traefik, allowing for on-the-fly routing changes without restarting Traefik.
*   **API Routing**: Traefik routes `api.${DOMAIN}` to the `m3tal-api.service` (Go API daemon) running directly on the host at `http://host.docker.internal:8080`. This is configured via `/docker/dynamic/api.yml`.
*   **Dashboard Routing**: When `DASHBOARD_EXPOSE_MODE=traefik`, Traefik routes `dash.${DOMAIN}` to the `m3tal-dashboard` container, leveraging the Traefik labels added by `m3tal-compose.traefik.yml`.

    ```yaml
    # Example: /docker/dynamic/api.yml (for API daemon routing)
    http:
      routers:
        api-router:
          rule: "Host(`api.${DOMAIN}`)"
          service: api-service
          entrypoints:
            - web
      services:
        api-service:
          loadBalancer:
            servers:
              - url: "http://host.docker.internal:8080" # M3TAL API daemon on host
    ```

### 🔌 Port Map

Understanding the port landscape is key for network configuration and troubleshooting:

| Port | Service                               | Access                                                                       |
| :--- | :------------------------------------ | :--------------------------------------------------------------------------- |
| 80   | Traefik HTTP entry point              | Public (when Traefik is active and domain points to host)                    |
| 8080 | M3TAL API daemon (Go `m3tal-api.service`) | Host-local access only (accessed by Dashboard container via `host.docker.internal`) |
| 8081 | Traefik dashboard                     | Host-local only (accessed via `http://localhost:8081` for Traefik's own UI)  |
| 8082 | M3TAL Dashboard                       | Direct port binding (when `DASHBOARD_EXPOSE_MODE=local`) or via Traefik (`dash.${DOMAIN}` when `DASHBOARD_EXPOSE_MODE=traefik`) |

## 🚀 M3TAL CLI Command Reference

Here's the complete command-line interface guide for M3TAL.

### `m3tal` / `m3tal ui`

Launches the M3TAL Linux Desktop Application. This command is typically used on a desktop environment where a graphical interface is desired.

**Usage Example:**

```bash
m3tal
# Or explicitly:
m3tal ui
```

### `m3tal headless [port]`

Starts M3TAL in headless mode. This is ideal for home servers or environments without a graphical interface. The M3TAL API daemon will start (if not already running), and the system will be manageable via the web dashboard or CLI. If `port` is omitted, it defaults to the `API_PORT` defined in `/etc/m3tal/.env` (default 8080).

**Usage Example:**

```bash
# Start in headless mode, using the default API port
m3tal headless

# Start in headless mode, explicitly setting the API port to 9090
m3tal headless 9090
```

### `m3tal stats`

Prints instant host system, GPU, thermal, and storage metrics directly to the terminal. Provides a quick snapshot of your server's health and resource utilization.

**Usage Example:**

```bash
m3tal stats
```

### `m3tal doctor`

Performs a pre-flight health check of the M3TAL system. This command verifies critical dependencies and configurations:
*   Docker connectivity and daemon status.
*   Validity of the `/etc/m3tal/.env` file.
*   Availability of required ports (e.g., 80, 8080, 8082).
*   Readiness of the `m3tal-api.service`.

**Usage Example:**

```bash
m3tal doctor
```

### `m3tal config wizard`

Launches an interactive wizard to configure the `/etc/m3tal/.env` file. This is the recommended way to set up M3TAL's core environment variables, guiding you through essential settings like `DOMAIN`, `DASHBOARD_EXPOSE_MODE`, and other crucial parameters.

**Usage Example:**

```bash
m3tal config wizard
```

### `m3tal config set KEY VALUE`

Sets a single environment variable in `/etc/m3tal/.env` to the specified value. This is useful for quick, non-interactive configuration updates.

**Usage Example:**

```bash
# Set the primary domain for Traefik routing
m3tal config set DOMAIN myhomelab.net

# Configure the dashboard to use Traefik for exposure
m3tal config set DASHBOARD_EXPOSE_MODE traefik
```

### `m3tal config get KEY`

Reads and prints the current value of a single environment variable from `/etc/m3tal/.env`.

**Usage Example:**

```bash
# Get the currently configured domain
m3tal config get DOMAIN

# Check the dashboard exposure mode
m3tal config get DASHBOARD_EXPOSE_MODE
```

### `m3tal config scan`

Lists all environment variables defined across all known M3TAL stacks, providing a comprehensive overview of your system's configuration footprint. This command helps identify variables used by various compose files.

**Usage Example:**

```bash
m3tal config scan
```

### `m3tal config list`

Prints the entire contents of the current `/etc/m3tal/.env` file to the terminal, showing all configured environment variables and their values.

**Usage Example:**

```bash
m3tal config list
```

### `m3tal dashpass [username] [password]`

Updates a user's password for the M3TAL Dashboard, storing it securely in `/docker/users.json`. If `username` and `password` arguments are omitted, the command will launch an interactive prompt to guide you through the process.

**Usage Example:**

```bash
# Interactively set or update dashboard user password
m3tal dashpass

# Set initial dashboard credentials for user 'admin' with password 'supersecurepass'
m3tal dashpass admin supersecurepass
```

### `m3tal dash up`

Pulls the latest dashboard Docker Compose configuration (`m3tal-compose.yml`, `m3tal-compose.local.yml`, `m3tal-compose.traefik.yml`) from GitHub, then starts or updates the `m3tal-dashboard` container according to the `DASHBOARD_EXPOSE_MODE` setting in `/etc/m3tal/.env`.

**Usage Example:**

```bash
# Ensure dashboard is running and up-to-date
m3tal dash up
```

### `m3tal dash down`

Stops and removes the `m3tal-dashboard` container and its associated network resources.

**Usage Example:**

```bash
m3tal dash down
```

### `m3tal dash restart`

Restarts the `m3tal-dashboard` container. Useful for applying configuration changes or resolving minor issues.

**Usage Example:**

```bash
m3tal dash restart
```

### `m3tal dash logs`

Streams the aggregated logs from the `m3tal-dashboard` container to your terminal, providing real-time insight into its activity.

**Usage Example:**

```bash
m3tal dash logs
```

### `m3tal dash status`

Shows the current status of the `m3tal-dashboard` container (e.g., `running`, `exited`, `restarting`).

**Usage Example:**

```bash
m3tal dash status
```

### `m3tal up`

Runs `docker compose up -d` across *all* `*-compose.yml` files found in the `/docker/` directory. This command starts or updates all your defined services and the core M3TAL stacks (like Traefik and Cloudflared).

**Usage Example:**

```bash
# Start or update all M3TAL services and user-defined stacks
m3tal up
```

### `m3tal down`

Runs `docker compose down` across *all* `*-compose.yml` files in the `/docker/` directory. This stops and removes all containers, networks, and volumes defined in those stacks.

**Usage Example:**

```bash
# Stop and remove all running M3TAL services and user-defined stacks
m3tal down
```

### `m3tal logs`

Streams aggregated logs from *all* currently running Docker containers managed by M3TAL. This provides a consolidated view of activity across your entire containerized environment.

**Usage Example:**

```bash
m3tal logs
```

## ⚙️ Advanced Topics

### Systemd Service Management

The core M3TAL API daemon runs as a `systemd` service named `m3tal-api.service`. This service is crucial for the CLI and Dashboard to interact with Docker and the M3TAL state database.

You can manage and monitor this service using standard `systemctl` and `journalctl` commands:

*   **Check Service Status**: View the current status of the API daemon, including whether it's active, its uptime, and recent logs.
    ```bash
    sudo systemctl status m3tal-api
    ```

*   **Restart the API Daemon**: If you've made manual changes to system files that the API daemon might need to recognize (e.g., firewall rules, `/etc/m3tal/.env` outside of `m3tal config` commands), restarting it can apply those changes.
    ```bash
    sudo systemctl restart m3tal-api
    ```

*   **Stop the API Daemon**: Temporarily halt the API daemon. This will prevent CLI commands that interact with the API (like `m3tal doctor`) and the Dashboard from functioning.
    ```bash
    sudo systemctl stop m3tal-api
    ```

*   **Start the API Daemon**: Manually start the API daemon if it's stopped.
    ```bash
    sudo systemctl start m3tal-api
    ```

*   **Follow API Daemon Logs**: Stream real-time logs from the API daemon, invaluable for troubleshooting.
    ```bash
    sudo journalctl -u m3tal-api -f
    ```

### Direct Docker Compose Commands (Fallback)

While the `m3tal` CLI provides convenient wrappers, you can always interact directly with Docker Compose V2 if needed, especially for debugging or advanced scenarios. All M3TAL's Docker Compose files are located in `/docker/`.

*   **List all Docker Compose projects**:
    ```bash
    docker compose ls
    ```

*   **Start a specific project (e.g., only the routing stack)**:
    ```bash
    cd /docker/
    docker compose -f routing-compose.yml up -d
    ```

*   **Stop a specific project**:
    ```bash
    cd /docker/
    docker compose -f routing-compose.yml down
    ```

*   **View logs for all services in a specific project**:
    ```bash
    cd /docker/
    docker compose -f routing-compose.yml logs -f
    ```

*   **Execute a command inside a service container**:
    ```bash
    cd /docker/
    docker compose -f m3tal-compose.yml exec m3tal-dashboard bash
    ```

*   **Build images for a specific project (if you have custom Dockerfiles)**:
    ```bash
    cd /docker/
    docker compose -f my-custom-stack-compose.yml build
    ```
