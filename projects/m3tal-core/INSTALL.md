# GETTING STARTED WITH M3TAL

This guide provides a complete, step-by-step setup for first-time M3TAL users.

---

## 1. Prerequisites

M3TAL requires a functional Docker environment. Ensure Docker Engine and Docker Compose V2 are installed on your system.

Verify your Docker installation:

```bash
docker --version && docker compose version
```

Expected output:
```
Docker version 2x.xx.x, build xxxxxxxx
Docker Compose version v2.xx.x
```

## 2. Install M3TAL via APT

M3TAL is distributed via an APT repository for easy installation and updates.

```bash
# 1. Add the GPG signing key
curl -fsSL https://jakej985-rgb.github.io/m3tal-apt-key/public.key | sudo gpg --dearmor -o /usr/share/keyrings/m3tal-archive-keyring.gpg

# 2. Add the APT repository
echo "deb [signed-by=/usr/share/keyrings/m3tal-archive-keyring.gpg] https://jakej985-rgb.github.io/m3tal-apt-key stable main" | sudo tee /etc/apt/sources.list.d/m3tal.list

# 3. Install
sudo apt update && sudo apt install -y m3tal
```

## 3. Run the Configuration Wizard

After installation, configure M3TAL using the interactive wizard. This sets up the primary configuration file at `/etc/m3tal/.env`.

```bash
sudo m3tal config wizard
```

The wizard will prompt you for several configuration values:

-   **`DASHBOARD_EXPOSE_MODE`**:
    -   `local`: The dashboard will be directly accessible via `http://YOUR_IP:8082`. This is suitable for LAN-only setups or when you do not intend to use Traefik for domain-based routing. This is the default and recommended for first-time setups.
    -   `traefik`: The dashboard will be accessible via `http://dash.DOMAIN`. This requires Traefik to be running and configured, and your `DOMAIN` variable to be properly set.
-   **`DOMAIN`**: The base domain name for your services if you are using Traefik. For `local` expose mode, `localhost` is a suitable default. If using `traefik` mode, set your actual domain (e.g., `example.com`).
-   **`ADMIN_PASSWORD`**: The default password for logging into the M3TAL dashboard. Change this from the default immediately.
-   **`DASHBOARD_SECRET`**: A secret key used by the dashboard for session management. A random string is generated by default.
-   **`API_TOKEN`**: A token for authentication with the M3TAL API. A random string is generated by default.
-   **`PUID` / `PGID`**: User ID and Group ID for containers to ensure correct file permissions on host volumes. Defaults are typically `1000`.
-   **`TZ`**: Your system's timezone (e.g., `America/Denver`).
-   **`BASE_STORAGE_PATH`**: The base directory on your host where M3TAL will store all data volumes. Defaults to `/mnt` (which corresponds to `/mnt` inside containers).
-   **Other paths (`MEDIA_PATH`, `CONFIG_PATH`, etc.)**: Subdirectories within `BASE_STORAGE_PATH` for specific types of data.
-   **`TRAEFIK_WEB_PORT` / `TRAEFIK_WEBHTTPS_PORT`**: The host ports Traefik will listen on for HTTP (default 80) and HTTPS (default 443) traffic.

Confirm the configuration when prompted.

## 4. Start the Routing Stack

M3TAL uses Traefik as a reverse proxy for routing external requests to internal services. This command starts Traefik and any other components defined in the `/docker/` directory.

```bash
m3tal up
```

This command executes `docker compose` for all `*-compose.yml` files located in `/docker/` (which is a symlink to `/opt/m3tal/stack/`). This will typically start `routing-compose.yml`, which includes the Traefik gateway and optionally Cloudflared.

## 5. Start the Dashboard

The M3TAL dashboard provides a web interface for managing your ecosystem.

```bash
m3tal dash up
```

This command performs the following actions:
1.  Downloads the latest dashboard compose files (`m3tal-compose.yml`, `m3tal-compose.local.yml`, `m3tal-compose.traefik.yml`).
2.  Reads the `DASHBOARD_EXPOSE_MODE` from `/etc/m3tal/.env`.
3.  Starts the `m3tal-dashboard` container with the appropriate configuration override (`m3tal-compose.local.yml` for `local` mode or `m3tal-compose.traefik.yml` for `traefik` mode).

## 6. Access the Dashboard

Open your web browser and navigate to the dashboard URL based on your `DASHBOARD_EXPOSE_MODE` setting:

-   **If `DASHBOARD_EXPOSE_MODE=local` (default):**
    Open `http://YOUR_IP:8082` (replace `YOUR_IP` with the actual IP address of your server).
    Example: `http://192.168.1.100:8082` or `http://localhost:8082`.

-   **If `DASHBOARD_EXPOSE_MODE=traefik`:**
    Open `http://dash.YOUR_DOMAIN` (replace `YOUR_DOMAIN` with the domain you configured during the wizard, e.g., `http://dash.example.com`). This requires proper DNS records pointing `dash.YOUR_DOMAIN` to your server's IP address.

## 7. Log In

Use the following credentials to log in:

-   **Username:** `admin`
-   **Password:** The `ADMIN_PASSWORD` you set during the configuration wizard (default is `admin_pass` if you did not change it).

**Important:** Change the default admin password immediately after your first login.
To change the dashboard password from the command line:

```bash
sudo m3tal dashpass
```

## Filesystem Contract

M3TAL relies on specific filesystem paths for its operation:

| Path                     | Purpose                                                              |
| :----------------------- | :------------------------------------------------------------------- |
| `/etc/m3tal/.env`        | Primary configuration file. Managed by `m3tal config wizard`.        |
| `/var/lib/m3tal/state.db`| SQLite state database. Auto-created by the API daemon.               |
| `/opt/m3tal/stack/`      | Canonical stack directory. Contains compose files and Traefik config.|
| `/docker`                | Symlink → `/opt/m3tal/stack/`. User-facing path for stack operations.|
| `/docker/users.json`     | Dashboard credential store. Managed by `m3tal dashpass`.             |

## Dashboard Access Modes

The M3TAL dashboard supports two access modes, controlled by the `DASHBOARD_EXPOSE_MODE` variable in `/etc/m3tal/.env`:

### Mode 1: `local` (Default)
-   **Configuration:** `DASHBOARD_EXPOSE_MODE=local`
-   **Mechanism:** M3TAL applies an override (`m3tal-compose.local.yml`) that directly binds the dashboard container's port 8082 to the host's `DASHBOARD_PORT` (default 8082).
-   **Access URL:** `http://HOST_IP:8082` or `http://localhost:8082`
-   **Usage:** Ideal for initial setup, local development, or environments where direct IP access is preferred and Traefik is not used for the dashboard. No domain configuration or Traefik setup is required for dashboard access in this mode.

### Mode 2: `traefik`
-   **Configuration:** `DASHBOARD_EXPOSE_MODE=traefik`
-   **Mechanism:** M3TAL applies an override (`m3tal-compose.traefik.yml`) that adds Traefik labels to the dashboard container. Traefik (running via `m3tal up`) then automatically discovers and routes traffic from `dash.${DOMAIN}` to the dashboard container on its internal port 8082.
-   **Access URL:** `http://dash.DOMAIN`
-   **Usage:** Recommended for production environments or when you want domain-based access to the dashboard, leveraging Traefik's routing capabilities (including potential SSL termination handled by Traefik). This requires Traefik to be running and your `DOMAIN` variable correctly configured.

## Docker / Compose Runtime

M3TAL uses **Docker Engine** and **Docker Compose V2** for container orchestration. These are hard dependencies.

-   The `m3tal up` command orchestrates all Docker Compose files ending in `*-compose.yml` located within the `/docker/` directory (which symlinks to `/opt/m3tal/stack/`). This includes the core `routing-compose.yml` for Traefik.
-   The `m3tal dash up` command specifically manages the `m3tal-dashboard` container. It ensures the correct compose override (`local` or `traefik`) is applied based on your `/etc/m3tal/.env` settings, pulls the necessary image, and starts the container.
-   To deploy new Docker-based applications, place your `my-app-compose.yml` file into `/docker/`.

## Deployment Lifecycle — Day 2 Operations

To add a new Docker stack or service to your M3TAL ecosystem:

1.  **Place Compose File:** Create your Docker Compose file (e.g., `my-app-compose.yml`) and place it in the `/docker/` directory.
2.  **Configure Environment Variables:** If your compose file requires specific environment variables, set them in `/etc/m3tal/.env` using `sudo m3tal config set KEY value` or by rerunning `sudo m3tal config wizard`.
3.  **Start/Update Stacks:** Run `m3tal up` to deploy or update all services defined in the `/docker/` directory.

## Traefik Routing Architecture

Traefik, deployed via `routing-compose.yml`, acts as the central reverse proxy:
-   It binds to port 80 (and 443 if configured) on the host system to serve HTTP (and HTTPS) requests.
-   It uses Docker labels to automatically discover services running in Docker and route traffic to them.
-   It also loads dynamic routing configuration from `/etc/traefik/dynamic` (which hot-reloads on changes).
-   It routes `api.${DOMAIN}` to the M3TAL API daemon (running on the host at `http://host.docker.internal:8080`) via a file provider config (`/etc/traefik/dynamic/api.yml`).
-   It routes `dash.${DOMAIN}` to the `m3tal-dashboard` container when `DASHBOARD_EXPOSE_MODE=traefik`, configured by Traefik labels within `m3tal-compose.traefik.yml`.

## Service Management

The M3TAL API daemon runs as a systemd service. You can manage and monitor it using standard systemd commands:

-   **Check service status:**
    ```bash
    systemctl status m3tal-api
    ```
-   **View real-time logs:**
    ```bash
    journalctl -u m3tal-api -f
    ```
-   **Restart the service:**
    ```bash
    sudo systemctl restart m3tal-api
    ```

## Port Map

The following ports are commonly used by M3TAL components:

| Port | Service                               | Access                                    |
| :--- | :------------------------------------ | :---------------------------------------- |
| 80   | Traefik HTTP entry point              | Public (if Traefik is exposed)            |
| 8080 | M3TAL API daemon (Go)                 | Host-local                                |
| 8081 | Traefik dashboard (read-only)         | Host-local only                           |
| 8082 | M3TAL Dashboard                       | Direct port (local mode) or via Traefik (traefik mode) |

## Firewall Note

If Traefik is enabled and exposed to the public internet, ensure your firewall allows incoming traffic on port 80 (and 443 for HTTPS). For systems using `ufw`:

```bash
sudo ufw allow 80/tcp
# If using HTTPS
# sudo ufw allow 443/tcp
sudo ufw enable # if not already enabled
```
